# 手動視聴ヘルパー

## 配布物と役割

- `SR-Mission-Runner-Mobile.user.js` v1.3.1: iPhone Safari + Userscripts向け。SHOWROOMの実際の `/lite/{slug}` 配信を自分で視聴し、目安時間を確認して手動で記録・移動する。
- `Mixch-Watch-Helper-Mobile.user.js` v0.2.1: ミクチャの公開 `/u/{id}/live` に対応した視聴メモβ。**Safariでの視聴コイン付与と現行の獲得条件は未検証**。公式ミッション達成ツールとは呼ばない。
- ポータルへの組込みではない。人物情報・子サイト・feed・Next.jsのUIは変更しない。

## 記録と切り替え

SHOWROOMは日本時間03:00と15:00を境に記録を分ける。08:00に10件なら同日14:59も10件、15:00は新しい枠の0件。端末のタイムゾーンには依存しない。閉じている間に切り替わった場合は、次に開いた時に新しい枠を読む。常駐・バックグラウンド動作は不要。

公式ヘルプ「ミッションについて」を2026-09-11に通常のブラウザで確認した。旧ヘルプから現在のFAQへ遷移し、ミッションのページを開いた。
- 旧入口: https://support.showroom-live.com/hc/ja/articles/22702944583065
- 現行: https://showroomsupport.notion.site/a7b31183dee54d11a0065c92a3af7469
- デイリーミッションは03:00–14:59 / 15:00–02:59。
- 同じ配信中に切り替えをまたいでも、同じ配信を引き続き視聴して新しい枠を再達成することはできない。
- 達成した後の「受取」もユーザーが公式画面で行う必要がある。

開いたプレイヤーのまま切り替えを検知したら計測を停止し、一覧から別の配信へ移るよう表示する。SHOWROOMはnao.qaの表示済み一覧からルームslugと開始日時を読み、端末で記録した時刻との組み合わせで同じ継続配信を候補から除外する。公式の配信ID・達成状態を取得したものではない。開始日時不明または古い表示の記録済みルームは安全側で除外し、新しい開始日時が最後の記録時刻より後と確認できた場合に候補へ戻す。

ミクチャは「端末の視聴日記」として日本時間0時に区切る。**これは実装上のメモ区切りで、現在のコインリセット条件を確認したものではない**。公式サイトの公開ライブリンクは確認したが、公式のコイン案内 `https://mixch.tv/p/21x4faqv` には古いキャンペーン条件が含まれ、現行仕様と確認できないため、コイン数・日次上限を現在の条件として採用しない。まず1ルームを通常どおり視聴して、公式アプリ側で付与を確認する。

## 公式の件数と区別する

表示は常に「端末の記録」。再生の進んだ時間が30/32/35秒に達しても、自動で達成・受取・次ルーム移動はしない。「記録して次へ」を本人が押すと1件記録する。SHOWROOMでは同じ配信を重複記録しない。同じルームでも新しく始まったと確認できる配信は別に扱う。ミクチャβは引き続き同じ日の同じルームを除外するローカル仕様。

端末の記録には、アプリや他ブラウザで視聴した件数を自動加算しない。任意の公式進捗表示とは別に管理する。「記録の調整・あとで見る」で確認した合計件数に合わせられる。手入力の件数にはルームID情報がないため、その分の重複ルーム除外はできない。v1.0.2の当該時間帯のタイマー到達記録は引き継ぐが、公式達成に昇格させない。

## フォローとお気に入り

「フォロー画面」は同じ人の公式プロフィールを新しいタブで開く入口。フォロー済み判定やフォローボタンの自動クリックはしない。必要なログインとフォローは本人が行う。プロフィール上でタイマーを起動したり配信へ送り返したりしない。

「あとで見る」はUserscripts内のローカルなブックマークであり、公式フォローとは別。時間帯の切り替えやこの枠の記録のリセットでは消えない。削除は個別の「削除」ボタンから行う。

## 動作範囲・安全境界

- Safari拡張の有効化と対象サイトへの許可が必要。iPhone Chromeやネイティブアプリを操作しない。
- パスが `.user.js` で終わる配布URLをSafariで開き、Userscriptsの拡張ポップアップからInstall / re-install。Userscripts本体アプリやDriveへの保存は不要。公式: https://github.com/quoid/userscripts
- DOM上のvideo/audioの再生時間が進んだ区間だけを計測する。停止・未再生・読み込み中・非表示・アプリ移動・大きい時間飛びは計上しない。クロスオリジンiframe等でプレイヤーを確認できない場合は数えない。
- 約2.5秒ごとのチェックポイントと中断操作で途中の計測を保存。OSによる突然の終了では直前の未保存分を失う場合がある。保存失敗時は移動しない。
- 記録は同じUserscriptsの保存領域内のみ。他端末・他ブラウザ・複数アカウントとは同期しない。1つの巡回を1タブで使う。GMストレージに跨タブの原子的ロックはなく、複数タブの同時書込みは保証しない。
- 秘密情報、Cookie、パスワードを読み出さない。遠隔コード読み込み・第三者へのデータ送信なし。SR v1.3.1の公式進捗表示に限り、本人が操作した同一オリジンの読取専用GETを許可する。
- 自動フォロー、ギフト、コメント、投票、報酬受取、再生開始、アクセス制限回避、視聴実績の偽装を行わない。手動補助だから規約に適合すると保証するものではない。

## テスト

`src/lib/watch-runners.test.ts` は既存 `pnpm test` に含まれる。時刻境界、途中記録、重複除外、手入力、旧版の引継ぎ、不正URL、再生時間の計測、独立したミクチャ日記を検査。

`tools/watch-runners.browser.mjs` は隔離したPlaywrightで実行する。`PLAYWRIGHT_MODULE_ROOT` にPlaywrightを含むnode_modules、`RUNNER_TEST_ARTIFACTS` にリポジトリ外の出力先を指定する。すべてのリクエストを架空のルーム・プレイヤーで置換する。実サービスにフォローや視聴を実行せず、公式報酬・実機iPhoneは検証対象外。390 / 430 / 1280pxで両スクリプトを検査する。

## 取得済み配信の再入室防止（v1.1.1）

- 「今回の周回キュー」「時間帯ごとの件数」「取得済み配信の除外履歴」を分離。再開・ジャンル変更・03:00/15:00の枠切替・件数リセットでも除外履歴は残る。件数だけが新しい枠の0になる。
- 候補を作る時と「次へ」を押した時に、最新の保存履歴を読み直して除外。すでに開いていた配信が記録済みなら計測を止め、手動の「次の未記録へ」を案内する。勝手にページを移動しない。
- 「取得済みなので除外」は、旧版や公式アプリで既に取得した配信を待ち時間なしで除外する手動操作。**件数は増やさない**。公式で確認した合計件数は別途「件数を合わせる」で入力する。
- v1.0.2の保存領域に残っているcompletedの記録を初回だけ引継ぎ。前のリセットや新しい周回で上書きされて失われた記録は復元できず、公式の獲得履歴も自動取得しない。読み取れた旧版のタイマー記録を公式獲得に昇格させない。
- 除外はルームごとの最後の記録時刻を保存する保守的方式。新しく観測した配信開始がその記録より後なら別配信として扱う。開始時刻を取得できない場合は記録済みルームを除外したままにする。ソースが古い場合などに新しい配信も候補から外れることはある。
- 除外履歴・お気に入りはこの端末のUserscripts内のみ。公開repoに視聴履歴・個別ルームの趣向・アカウント情報は保存しない。テストでは架空のルーム名・日時だけを使用する。


## 公式トップからの開始（v1.2.0）

- `https://www.showroom-live.com/` と `/onlive` を開始ページに追加。nao.qaも継続対応し、同じUserscripts保存キー・取得済み履歴・時間帯件数を共有する。開始した一覧をキューに保存し、「中断・一覧へ」はその一覧へ戻す。旧キューに戻り先が無い場合は公式トップへ戻る。
- 2026-09-11に未ログインの公式モバイル/PC画面で `article.onlivecard`、`a.ga-onlive-click`、同じli内の `.onlivecard-time.is-onlive` を確認。配信中マーカーを持ち、非表示になっていないカードだけを候補とする。TODAY'S PICK・予告・プロフィール単体リンクを拾わない。カードが読み込まれていなければ待機表示にする。
- 候補は現在の画面に読み込まれた分。ページの表示・ジャンル変更後に再読取するが、スクリプトが自動スクロールや裏側APIで候補を取得することはない。移動時には/lite/へ正規化する。
- 公式カードの開始表示は確認時点でHH:MMのみ。日付を推測で付けずstartedAt不明として扱うため、取得済みルームは保守的に除外する。新しい配信か判断する日時が必要なら、フルの開始日時があるnao.qa側で候補を確認する。日時が判明しない配信を勝手に未取得へ戻さない。
- メタデータの対象はSHOWROOM両ホストへ拡張するが、実行時にトップ・/onlive・/lite/だけを許可。ログイン・プロフィール・課金ページを操作しない。
- ミクチャv0.1.1は共通エンジン更新とリセット表示の整合のみ。ミクチャにSHOWROOM公式入口を追加するものではない。


## 公式進捗の読取専用表示と画面切替への対応（SR v1.3.1 / Mixch v0.2.1）

### SHOWROOMの公式進捗は試用機能

- 公式トップ・/onliveから選んだカードの `data-room-id` を保存し、対象IDを確認できる公式ページ内だけで `/api/mission?room_id=...` を読む。通常の配信視聴や一覧操作では通信しない。ID不明なら通信せず案内を出す。
- 公式クライアントの公開JSで、GET、`genre_list`、daily、`current_period`、day/night、continuous_mission/single_missionの`mission_id/title/current_value/target_value/is_active`を確認した。未ログインの実レスポンスは `{}`。ログイン済みの実レスポンスは未照合なので、読み取り成功を保証しない。
- UIの「公式の進捗を読む」を本人が押した時だけGET。任意の「この画面で60秒ごとに読む」は初期OFF・保存しない。画面外では通信しない。未知の形式・失敗・時間帯切替で自動読取をOFFにする。連打は5秒間隔で抑制。
- 対象ホストを厳密に検証し、GET / credentials:same-origin / redirect:error / cache:no-store、8秒タイムアウト。報酬受取エンドポイント、POST、Cookie文字列の読出し、認証情報のコピー、別ホストへの転送はしない。
- 確認できるデイリーの視聴ミッションだけを元のタイトル・現在値/目標値で表示する。秒数・件数等の単位を推測せず、端末の件数に自動加算しない。複合ミッションは解釈を避けて表示対象外。
- 公式データは画面内の一時表示のみ。全文レスポンス・アカウント情報・公式進捗をGM保存や公開repoへ保存しない。値が取得できない場合は不明と表示し、0件や達成済みに変換しない。
- **公式の進捗は、配信別の獲得履歴一覧ではない。** 合計値から特定の配信を取得済みと推定しない。過去の配信を全面的に自動除外する機能は未実装。既存の端末履歴と手動除外は維持する。
- 一次実装ソース（2026-09-11読取）: https://client-cdn.showroom-live.com/assets/ad96fa3a65cdeec6dc7be9a422b6d4f3602198ee/_nuxt/C-IC7ZhN.js 。非公開APIの将来互換性を保証しない。失敗しても通常の視聴・端末記録を壊さない。

### ミクチャの「次へ」継続（v0.2.1）

- 配信一覧で見えていた候補を最大15分、Userscriptsのローカル領域へ一時保存する。単独で配信ページを開いて「この配信を計測」した場合も、この候補をキューへ補充して「記録して次へ」の1タップで次の未記録配信へ進める。
- 一時候補は公式の獲得履歴ではなく、直近に画面へ表示された公開ライブへのリンクだけ。15分を超えた候補は使用しない。別端末・別ブラウザとは同期しない。
- 候補が残っていない場合、「記録して次へ」は一覧へ戻す。そこから新しい候補を読み、本人が再度開始する。バックグラウンドで勝手に周回しない。

### ミクチャの起動・再表示

- サイト内でページ全体を再読込しない画面切替に対応。対応URLに入った時に起動し、別のルームへ切り替わったら前のルームのタイマーとイベントリスナーを停止する。プロフィール・対象外画面ではパネルを出さない。
- サイトの再描画でパネルだけが外れた場合、同じパネルを付け直す。二重注入では重複タイマー・パネルを作らない。監視間隔600msで、非表示中は画面の再構築を行わない。
- この修正は再現可能なコード上の弱点への対策。オーナーのスクリーンショットの原因が、この問題か未インストール・サイト権限等かまでは確定していない。
- 配布物はSRとは別にUserscriptsへインストールする。`mixch.tv`のサイト許可とスクリプト有効化が必要。新版の実機iPhoneと公式コイン付与は未検証のままβとする。
